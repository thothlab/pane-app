Отдельное окно **Logcat** на каждое устройство показывает поток `adb logcat`
в реальном времени. Строки пишутся в SQLite (примерно за последние сутки на
устройство), поэтому история переживает переоткрытие окна, а фильтрация и
пагинация идут по индексу, а не по памяти.

Открыть: на карточке устройства (вкладка **Devices**) — кнопка **Logcat**.
Каждое устройство открывается в своём окне.

## Панель инструментов

| Элемент | Что делает |
| --- | --- |
| **Tail** | Follow-режим: вид прилипает к концу потока. Прокрутка вверх выключает Tail; прокрутка вниз до конца — включает обратно. |
| **Pause** | Замораживает вид (backend продолжает писать в БД). Пока заморожено, справа копится счётчик «+N» новых совпадающих строк. |
| **Clear** | Удаляет строки этого устройства из БД. |
| **Export** | Пишет **всю** отфильтрованную историю (не только загруженное окно) в `.log` в формате `threadtime` — открывается в любом лог-вьювере. |

## Фильтр

Строка с иконкой **▽** — это filter DSL (фокус — `⌘⇧F`). Термы через пробел
объединяются по **AND**; тот же грамматика компилируется в SQL, что и
применяется к БД.

### Ключи

| Ключ | С чем матчится | Пример |
| --- | --- | --- |
| `tag:` | substring по тегу (case-insensitive, Unicode) | `tag:OkHttp`, `tag:*Worker` |
| `msg:` / `message:` | substring по тексту сообщения | `msg:timeout`, `message:"connection reset"` |
| `level:` | уровень или диапазон (см. ниже) | `level:E`, `level:W..F` |
| `pid:` | точный PID | `pid:1234` |
| `app:` | процесс приложения по имени пакета (см. ниже) | `app:ru.example.app`, `app:example` |

Ключи **case-insensitive**. Значение с пробелами или спецсимволами — в
кавычки: `tag:"Pane Helper"`.

### Уровни

`level:` принимает как одиночный уровень, так и диапазон. Токены:
`v`/`verbose`, `d`/`debug`, `i`/`info`, `w`/`warn`, `e`/`error`,
`f`/`fatal`, `s`/`silent`.

```text
level:E          # только error
level:W..F       # warn и выше (warn, error, fatal)
level:..E        # error и ниже
level:W..        # warn и выше (без верхней границы)
```

### Фильтр по приложению — `app:`

`app:` матчит процесс по **substring** имени пакета. Имена берутся из
периодического снимка `ps -A` (раз в ~10 c), так что `app:example` поймает
`ru.example.app`. Значение резолвится в PID'ы, и по ним фильтруются строки —
в самом логе имени процесса нет, только PID.

```text
app:ru.example.app                     # только процесс этого приложения
app:ru.example.app,!ru.example.helper  # приложение, но без его helper-процесса
```

Важное поведение (с 0.2.6): если `app:X` **не совпал ни с одним живым
процессом** (приложение не запущено или ещё не попало в снимок `ps`), вид
будет **пустым** — а не показывает весь лог устройства. Пустой результат
здесь означает «строк этого приложения сейчас нет», а не «фильтр не
сработал».

:::note
Атрибуция по `app:` работает только по **живым** PID из `ps -A`. Строки
процесса, который уже завершился (или писал в лог до открытия окна), под
`app:X` не попадут — их PID нет в снимке. Для точечного случая используйте
`pid:` напрямую.
:::

### Отрицание

Префикс `!` перед термом исключает совпадения; `!` перед значением внутри
списка — исключает это значение.

```text
!tag:LeakCanary            # выбросить весь LeakCanary
tag:!Spam,!Noise           # тег, где нет ни Spam, ни Noise
level:E !msg:keepalive     # ошибки, но не про keepalive
```

### Запятая — это OR

Внутри одного ключа запятая перечисляет альтернативы (positives — OR,
negatives — «ни одно из»):

```text
tag:OkHttp,Retrofit        # tag содержит OkHttp ИЛИ Retrofit
pid:1234,5678              # любой из двух PID
```

### Barewords и regex

Терм без двоеточия — substring одновременно по **тегу или сообщению**.
Терм с префиксом `~` — регулярное выражение (Rust-синтаксис), матчит по
**тегу или сообщению**:

```text
timeout                    # tag ИЛИ message содержит "timeout"
~^Worker.*failed$          # regex по тегу или сообщению
!~keepalive                # исключить всё, что матчит regex
```

В отличие от фильтра captures, здесь **regex есть** — лог часто скамишь по
точным шаблонам.

## Поиск (`⌘F`)

Отдельно от фильтра есть поиск подстроки (`⌘F`). Он **не сужает** таблицу, а
подсвечивает совпадения и прыгает между ними (`Enter` — вперёд,
`Ctrl+Enter` — назад) по всем колонкам. Фильтр (`⌘⇧F`) формирует поток;
поиск (`⌘F`) находит в уже отфильтрованном.

## Иконки в строке фильтра

- **×** — очистить строку фильтра целиком.
- **☆** — сохранить текущий фильтр в sidebar (список слева). Сохранённые
  фильтры переживают перезапуск; сохранение под существующим именем
  **обновляет** его. Списки captures и logcat раздельны.

## Колонки

Time · App · PID · Tag · Level · Message. Ширину Time/PID/App/Tag можно
тянуть за правый край заголовка (двойной клик — сброс). Правый клик по
заголовку — скрыть/показать колонки. Настройки сохраняются между запусками.
Колонка **App** — имя процесса по PID (из того же снимка `ps -A`); для
строк, чей PID не резолвится, — пусто.

## Выделение и копирование

Клик выделяет строку, `Shift`-клик — диапазон, `⌘`/`Ctrl`-клик — переключает
одну. `⌘C` копирует выделенное как полные `threadtime`-строки, `⇧⌘C` — только
сообщения. Правый клик → **View message** открывает оверлей с полным
сообщением и кнопкой форматирования JSON.

## Подсветка синтаксиса

Токены фильтра подсвечиваются по мере ввода: известные ключи — accent
(синий), неизвестный ключ — красный с dotted-underline (backend отбросит
терм), `!` — красный, `:` — muted.
